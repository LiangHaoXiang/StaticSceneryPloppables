## 当前游戏版本的补充核验（2026-11-16，实施 #16 前）

**重要更正：不能把 `thumbnail://` 理解成「不存在缩略图时自动启动相机渲染」。**我用本机游戏 1.6.4f1 的 `Game.dll`（2026-11-11，12,180,992 字节，SHA-256 `f076df4b70aa0f21a80345e03a052ca2273bc6754f41dab7e63d837837a43745`）反编译 `Game.UI.GameUIResourceHandler.TryThumbnailRequestAsync` 与 `Game.UI.Thumbnails.ThumbnailCache.GetThumbnail`：前者只用 `PrefabID` 查 prefab，再通过 `thumbnailCache.GetThumbnail(prefab,width,height,camera)` 查缓存；`info == null` 时返回 `Thumbnail not found`。后者只从现有 `m_CacheData` 字典按 `(obj.name,width,height)` 找数据；在该链路中**没有为未缓存的原版建筑自动建立渲染任务**。因此本调研下文「无 icon 时返回 thumbnail:// URI」只是**字符串/候选请求路径**，不是图片生成成功的保证。Find It 的 `onError` 分类图回退正是必要的。原建议「只显示可见 10 个并发 1 张动态缩略图」无法保证产出实际建筑图，必须先证明缓存覆盖，或另设计独立生成管线（如离线渲染/素材制作）再实施。

本轮曾构建一个按需 thumbnail:// 实验实现，但在该核验后已撤回未提交代码、删除实验本地部署，**没有推送或发布**。此结论纠正此前关于 `thumbnail://` 会为每个建筑触发相机渲染的推断。

**已完成原版归档图集条目清点，不等于游戏运行时所有图集闭包。**本机游戏内容的 `.cok` 是 ZIP；只读枚举 24 个 `Blob*.cok` 中全部 12 个 `.Atlas`，按当前游戏 `TextureAsset.ReadHeader`、`AtlasAsset.LoadAdditionalData`、`BinaryReaderExtensions.ReadAtlasEntries/ReadAtlasEntry` 指定的格式离线解析，并以每个文件完整消费到 EOF 校验：总计 **1009 个条目、1009 个不同名称**（根包 `Brands` 193、`Builtin` 695、`NewAtlas` 18、`BeachProperties` 10、`NewThumbnails` 16；其余更新/DLC 包合计 77）。其中精确包含 `_L1_`、`_L3_`、`_L5_` 的条目均为 **0**；例如 `EU_ResidentialLow01_L1_2x2` 和 `EU_ResidentialLow03_L1_2x2` 在这些图集里任意尺寸均无精确名称匹配。当前 `ThumbnailCache.LoadAtlas` 把每个图集项建成 `(name,width,height)` 键，`GetThumbnail(prefab,128,128)` 查询 `(prefab.name,128,128)`；**对于按等级命名的原版生长建筑，仅按需请求 `thumbnail://` 不会从这 12 个图集取得建筑图，更不会触发新图渲染。**

## 一句话结论

AIL 在发布包中携带大量事先生成的 PNG/SVG：启动时解包到 `ModsData/AssetIconLibrary/.Thumbnails`，建立「prefab 名称／`类型.名称` → `coui://ail/…`」索引，并给**匹配到的** prefab 的 `UIObject.m_Icon` 写入素材 URI。`ImageSystem.GetIcon(prefab)` 读到这个 URI 就直接返回；`ImageSystem.GetThumbnail(prefab)` **优先返回同一个 icon**，仅无 icon 时才退化为 `thumbnail://…?width=128&height=128` 候选 URI（是否实际有图，取决于游戏缩略图缓存）。**原图标不是 SVG 的同义词；AIL 主体恰是预制 PNG。** [AIL 项目打包逻辑](<../../.research/mod-sources/AssetIconLibrary-CSII/AssetIconLibrary/AssetIconLibrary.csproj#L23-L31>)；[AIL 加载索引及 URI](<../../.research/mod-sources/AssetIconLibrary-CSII/AssetIconLibrary/Utilities/IconLibraryUtil.cs#L19-L40>)；[AIL 替换逻辑](<../../.research/mod-sources/AssetIconLibrary-CSII/AssetIconLibrary/IconReplacerSystem.cs#L110-L163>)；[游戏 ImageSystem](<../../.research/treectl/gamefull/Game.UI/ImageSystem.cs#L60-L115>)。

## 1. 预制图片的来源、存储和三档样式

1. 仓库目录 `AssetIconLibrary/Thumbnails/` 存图片素材；构建目标使用 `AutoZipFolder` 把这些文件压成部署包 `.Thumbnails/Pack`，不是启动游戏时逐项渲染 prefab。代码随后从邻近程序集的 `.Thumbnails/Pack.zip` 解压归档中的 zip 分块，完成后在 `ModsData/AssetIconLibrary/.Thumbnails` 留 `.version`；若版本与程序集相同，则跳过解包。解包源是分发包而非游戏缩略图相机。仓库确有如 `AssetIconLibrary/Thumbnails/ColoredPropless/BuildingPrefab.EU_ResidentialLow01_L1_2x2.png` 的 256×256 PNG；**并非所有建筑都有同名素材**。[打包目标](<../../.research/mod-sources/AssetIconLibrary-CSII/AssetIconLibrary/AssetIconLibrary.csproj#L23-L31>)；[解包、版本与分块](<../../.research/mod-sources/AssetIconLibrary-CSII/AssetIconLibrary/Utilities/IconUnpackerUtil.cs#L12-L67>)；[安装路径](<../../.research/mod-sources/AssetIconLibrary-CSII/AssetIconLibrary/Utilities/FolderUtil.cs#L18-L31>)。
2. 默认样式 `ColoredPropless`，另有 `White` 和 `Colored`，这些是各自的**预制图目录**，需重启才生效。加载索引时先读取 `.Thumbnails` 根目录，然后读取当前选定样式子目录，后者的同名条目覆盖根目录；支持 `.svg`、`.png`、`.jpg`、`.jpeg`，因此不能因为 `GetIcon` 方法名就把结果描述成纯 SVG。默认 `OverwriteIcons=true`，可关闭以保留原版带图标的资产。[样式配置](<../../.research/mod-sources/AssetIconLibrary-CSII/AssetIconLibrary/Settings.cs#L29-L42>)；[样式选项](<../../.research/mod-sources/AssetIconLibrary-CSII/AssetIconLibrary/Settings.cs#L76-L98>)；[索引读取顺序](<../../.research/mod-sources/AssetIconLibrary-CSII/AssetIconLibrary/Utilities/IconLibraryUtil.cs#L19-L41>)；[格式/URI](<../../.research/mod-sources/AssetIconLibrary-CSII/AssetIconLibrary/Utilities/IconLibraryUtil.cs#L123-L146>)。

## 2. AIL 如何注入 UIObject，以及加载时序陷阱

1. `Mod.OnLoad` 把 `IconReplacerSystem` 注册到 `SystemUpdatePhase.PrefabReferences`，后台任务解包并准备素材索引；OnGamePreload 启用替换系统。准备完成即遍历 `PrefabSystem` 中的 prefab 列表，为匹配对象设置/补建 `UIObject`，并将 `m_Icon` 设为 `coui://ail/...`；关闭覆盖开关且 prefab 已有原版图标时则保持原值。这是对**内存 prefab UI 字段的替换**，不是修改建筑网格或在运行时渲染图片。[注册与异步准备](<../../.research/mod-sources/AssetIconLibrary-CSII/AssetIconLibrary/Mod.cs#L25-L79>)；[OnGamePreload/替换系统](<../../.research/mod-sources/AssetIconLibrary-CSII/AssetIconLibrary/IconReplacerSystem.cs#L20-L69>)；[遍历与匹配](<../../.research/mod-sources/AssetIconLibrary-CSII/AssetIconLibrary/IconReplacerSystem.cs#L72-L120>)；[写入 m_Icon](<../../.research/mod-sources/AssetIconLibrary-CSII/AssetIconLibrary/IconReplacerSystem.cs#L140-L170>)。
2. `handledPrefabs` 跳过二次处理：它在检查键是否有匹配之前就将 prefab 加入集合；一个当时没有匹配项的 prefab 后来新增映射也不会在同一会话内自动重新尝试。替换系统 `OnUpdate` 自行 `Enabled=false`，每次进图由 `OnGamePreload` 再启用；源码没有针对**日后创建的 SSP 克隆 prefab**的逐项回调。即使下一轮遍历看到 SSP 克隆，其名字 `SSP_S_<原版名>` 不等于原图键 `BuildingPrefab.<原版名>`，也不会凭前缀自动匹配。因此正确的互操作方案若需要给 SSP 克隆配专属图，应显式建立映射或复用原版对象的 icon URL，同时考虑初始化与显示时序。[`handledPrefabs` 以及键判断](<../../.research/mod-sources/AssetIconLibrary-CSII/AssetIconLibrary/IconReplacerSystem.cs#L20-L22>)；[先记录后检查](<../../.research/mod-sources/AssetIconLibrary-CSII/AssetIconLibrary/IconReplacerSystem.cs#L89-L120>)；[按 preload 重启](<../../.research/mod-sources/AssetIconLibrary-CSII/AssetIconLibrary/IconReplacerSystem.cs#L32-L50>)。

## 3. `GetIcon` 与 `GetThumbnail`：图标与缓存候选 URI 的区别

游戏 API 快照中，`ImageSystem.GetIcon(prefab)` 读取 `UIObject.m_Icon` 并 `ResolveUri`，没有自动生成图片；`ImageSystem.GetThumbnail(prefab)` **先调用 GetIcon**，有图即直接返回现成 URI；无图且 `noThumbnails=false` 时构造 `prefab.thumbnailUrl?width=128&height=128`（通常 `thumbnail://`）。调用 `GetThumbnail` **只取得字符串**，请求 URI 时当前 1.6.4f1 的 `ThumbnailCache` 只查现有图集，缺图返回错误；不能推断无 icon 的建筑都能得到图，也不能把分批请求当作分帧渲染机制。[游戏 ImageSystem:GetIcon/Thumbnail](<../../.research/treectl/gamefull/Game.UI/ImageSystem.cs#L60-L115>)。

- **Find It 的调用路径**：只为当前显示窗口 `startIndex..columns*(2+displayedRows)` 填 `PrefabIndexBase.Thumbnail`，并以 `??=` 缓存，`GetThumbnail` 代理 `ImageSystem.GetThumbnail(prefab)`，捕获异常后返回 `FallbackThumbnail`；分类兜底先由索引提供，分区建筑改用分区 prefab 的 `GetIconOrGroupIcon`。前端 `<img>` 加载失败时也切 `fallbackThumbnail`。设置 `NoAssetImage` 时仅非 hover 状态先显示兜底；它不是强制禁止所有 thumbnail 请求。Find It 在 PDX 配置里声明 `<Dependency Id="79634" />`，这是**平台安装强依赖**；C# 代码里只是 `IsAssetIconLibraryEnabled` 的模组名检测，图片实际仍走游戏 `ImageSystem`，没有直接调用 AIL 方法。[Find It 页面依赖](<../../.research/mod-sources/FindIt-CSII/FindIt/Properties/PublishConfiguration.xml#L175-L180>)；[Find It 模组检测](<../../.research/mod-sources/FindIt-CSII/FindIt/Mod.cs#L25-L34>)；[可见窗口填图及 fallback](<../../.research/mod-sources/FindIt-CSII/FindIt/Systems/FindItUISystem.Methods.cs#L31-L89>)；[分区分类图](<../../.research/mod-sources/FindIt-CSII/FindIt/Utilities/PrefabCategoryProcessor/ZonedBuildingPrefabCategoryProcessor.cs#L67-L80>)；[前端加载失败回退](<../../.research/mod-sources/FindIt-CSII/FindIt/UI/src/mods/PrefabItem/PrefabItem.tsx#L81-L96>)；[NoAssetImage 逻辑](<../../.research/mod-sources/FindIt-CSII/FindIt/UI/src/mods/PrefabItem/PrefabItem.tsx#L81-L95>)。
- **SSP 当前路径**：构建 catalog 时 `SafeIcon(source)` 用 `ImageSystem.GetIcon`，没有动态缩略图；原版建筑当时无 icon 就使用分区 SVG；前端再用自带分区 SVG 做请求失败兜底。SSP 为剥离版复制 `UIObject`，如果 icon 为空则写入 `src.thumbnailUrl`（**这是另一个实现层面的潜在动态 URI**，可影响剥离建筑自身在其他 UI 中的图标，但当前 catalog 的 `entry.IconUrl` 从 source 来而非 clone）。SSP 文件现有“仅 SVG 图标”等注释在 AIL 返回 PNG 的场景下已过时；只是注释不准确，不等于功能故障。[SSP SafeIcon 及目录图标](<../StaticSceneryPloppables/Systems/GrowableVariantSystem.cs#L297-L351>)；[SSP SafeIcon 定义](<../StaticSceneryPloppables/Systems/GrowableVariantSystem.cs#L622-L633>)；[SSP 克隆 icon 兜底](<../StaticSceneryPloppables/Systems/GrowableVariantSystem.cs#L707-L738>)；[SSP 前端图片失败处理](<../ssp-ui/src/mods/ssp-panel.tsx#L224-L256>)。

## 4. 设计/验证建议（未实施）

- **不要把 AIL 设为运行时强依赖**才能获得精确建筑图：自行显式引用 AIL 原版图片路径属于**可选互操作**，应先确认资源 URI 存在、是否已挂载，并为缺失素材保留分区图；不能硬编码所有 2,077 条都存在。
- 若不依赖 AIL，先确认目标建筑的 `thumbnail://` URI 对应的图集确实存在；当前游戏版本的请求处理只是**查缓存**，不是「请求一张就生成一张」。确认覆盖率后，才考虑可见项窗口化 + 限流/缓存 + `onError` 回退；未确认前切勿建目录时为所有 2,077 条请求图片。Find It 既窗口化也有隐藏图片预热组件（200 张/400ms），预热的是**加载现成 URI**，不会凭空创建图集。[Find It 窗口化](<../../.research/mod-sources/FindIt-CSII/FindIt/Systems/FindItUISystem.Methods.cs#L31-L72>)；[Find It 缩略图预热实现](<../../.research/mod-sources/FindIt-CSII/FindIt/UI/src/mods/AllThumbnails/AllThumbnails.tsx#L6-L47>)。
- 静态图片能否一并打包/复用还需确认具体素材来源与许可、包体、风格切换和同名图标冲突。仓库根 `LICENSE` 是 MIT 许可，**但不能仅据此推断从游戏/第三方提取或再分发的所有图像都已获得独立授权**；需逐项核实素材权利归属。[AIL 仓库许可](<../../.research/mod-sources/AssetIconLibrary-CSII/LICENSE#L1-L20>)。本轮只读研究**没有证明任何 SSP 全目录 icon 覆盖率，也没有实测新集成在游戏里的流畅程度**。
