# StaticSceneryPloppables 复盘与路线图（2026-11-12 重新梳理）

## 一、需求（用户原话归纳）

像 Find It 那样的操作界面和交互：列表显示**所有**原版分区建筑 → 选中 → 点地放置；
放置产物 = **无属性建筑壳 + 原版布局的地皮/板凳/垃圾箱/树木/花盆等装饰**（随机版本），
省去手动逐个摆装饰。一步式，不依赖任何无属性资产搬运模组。

## 二、上游一手源码调研结论（本轮新增，仓库已 clone 到 .research/mod-sources/）

### Find It（JadHajjar/FindIt-CSII）
- **不生成任何 prefab**。`ZonedBuildingPrefabCategoryProcessor` 直接索引**原版 BuildingPrefab 本体**
  （查询条件：`BuildingData + SpawnableBuildingData`），点击 → `ToolSystem.ActivatePrefabTool(原版prefab)`。
- 所以 Find It 放可生长建筑 = 放"有属性原版建筑"（带居民/岗位/装饰）——**不是我们想要的**，
  但证明：原版 BuildingPrefab 经 ActivatePrefabTool 放置是安全的（我们崩的不是这条路本身）。
- 面板 = Gameface(cohtml) UI：`FindIt/UI/src`（PrefabSelection/PrefabItem 等组件），
  C# 侧 `FindItUISystem` 用 binding/trigger 双向通信。这套 UI 可作为我们 M3 面板的参考实现。

### ctrlC（jk1422/ctrlC）—— 与我们目标同构，全部关键答案在这里
完整可放置图章链路（千万下载验证）：
1. **生成**：`CopySystem.CopyItems` 把场景实体转为 `AssetStampPrefab`：
   - 建筑本体 → `ObjectSubObjectInfo`（引用原版 BuildingPrefab，概率 100）
   - 地皮装饰 → `ProcessSubElements` 读建筑实体的 `SubArea` buffer（SpacePrefab 表面）
     转 `ObjectSubAreaInfo`（带节点坐标）
   - 树/道具 → 独立 `ObjectSubObjectInfo`（CopyTrees/CopyProps）
2. **注册**：`prefabSystem.AddPrefab(stamp, null, null, null)` 后**立即 `prefabSystem.Update()`**
   （反编译版 AddPrefabToSystem；一手源码 PlacementTool.UpdatePrefabSafe 用单体 `UpdatePrefab(prefab)`）
3. **激活放置（我们一直缺失的关键！）**：`PlacementTool : ObjectToolSystem` 自定义工具：
   ```csharp
   Enabled = true;
   TrySetPrefab(stampPrefab);          // 基类方法
   m_ToolSystem.activeTool = this;     // 直接指定活动工具
   base.mode = Mode.Stamp;             // ★ 强制图章模式，不经 ActivatePrefabTool 遍历
   ```
   注册于 `SystemUpdatePhase.ToolUpdate`（Mod.OnCreateWorld → updateSystem.UpdateAt<PlacementTool>）。
4. **持久化**：`AssetDatabase.user.AddAsset(path) + Save`（.prefab/.cid/meta.json 落盘）；
   启动时 `AssetDatabase.user.AddAsset(path, hash)` → `Load()` → `AddPrefab`（协程分帧加载）。

### 原版机制对照（反编译佐证）
- `ObjectToolSystem.Mode` 枚举有 `Stamp`；`CreateDefinitions(..., actualMode == Mode.Stamp, ...)`
  —— 放置定义生成按模式走**完全不同的管线**。
- `ObjectInitializeSystem` line 577：`prefab is AssetStampPrefab` 分支设置
  `GeometryFlags.Stampable|ExclusiveGround|WalkThrough|OccupyZone|HasLot`。
- `ObjectToolSystem` line 2430：`allowStamp = (ObjectGeometryData.m_Flags & Stampable) != 0`；
  line 2353：`!allowCreate && allowStamp && mode==Create → mode = Stamp`（自动切换，链路长）。
- **AddPrefab 的新 prefab 实体自带 Created/Updated 组件**（PrefabSystem line 143-144），
  下帧 PrefabUpdate 阶段的初始化系统扫 `WithAny<Created,Updated>` 处理（FindIt 同款查询）。

## 三、此前 26 天排查的重新解读

| 事实 | 新解释 |
|---|---|
| v1 克隆 BuildingPrefab 经 Find It 点击崩 | GC 堆损坏（JsonUtility 批量克隆）+ 走 Create 模式放克隆体 |
| v2 AssetStamp 图章经 ActivatePrefabTool 崩 | **Create 模式处理图章** → CreateDefinitions 以 isStamp=false 走建筑创建管线 → 未验证路径崩溃。ctrlC 同场景用自己的 PlacementTool+Mode.Stamp —— 大概率作者踩过同一坑 |
| v3 StaticObjectPrefab+PlaceableObject 崩 | 同为 Create 模式；且静态物体缺 BuildingData，定义生成走错分支 |
| 手动 PrefabSystem.Update() 在 Modification4B 崩 | 重入整个 PrefabUpdate 阶段；正确单体 API 是 `UpdatePrefab(prefab)`（ctrlC UpdatePrefabSafe 实证） |
| Find It 点原版建筑正常 | 原版 prefab 数据完整且本就为 Create 模式设计 |

**结论：崩溃主因 = 激活模式错误（Create vs Stamp），次要 = 克隆体数据损坏。**
此前"组件污染""资产身份"假说均非主因（真资产落盘管线后仍崩即为证）。

## 四、还缺什么（路线图）

### M1' 激活链路修复（当前最高优先级）
- [ ] 复刻 ctrlC `PlacementTool`（继承 ObjectToolSystem，Mode.Stamp，注册 ToolUpdate）
- [ ] AUTO-TEST 改走自己的 PlacementTool 激活（不再用 ToolSystem.ActivatePrefabTool）
- [ ] AddPrefab 后调 `prefabSystem.UpdatePrefab(stamp)`（单体刷新，非 Update()）
- 验收：空地图自动激活 → 半透明预览 → 左键放置成功不崩

### M2' 图章内容完整化（装饰）
- [ ] 建筑子物体（已有）
- [ ] 地皮：读源建筑 prefab 的 `ObjectSubAreas`（LotPrefab/SpacePrefab）转 `ObjectSubAreaInfo`
- [ ] 装饰随机：两案选一（与用户确认）
  - A. **生成时固化**：读源 prefab `ObjectSubObjects`（SpawnableObject 声明）按概率预抽一组写死进图章 —— 简单，但每个建筑固定组合
  - B. **放置时随机**：监听放置事件，对 stamp 实例跑原版式抽签（AreaUtils.SelectAreaPrefab + PseudoRandomSeed）动态生成装饰实体 —— 符合原版"每次不同"，工程量大
  - 折中：为每建筑预生成 K 个不同抽签结果的图章变体（K=3~5），玩家轮换放置也有随机感
- 验收：放置后地皮+装饰齐全，装饰组合有变化

### M3' 面板（Find It 式）
- [ ] Gameface UI 列表（参考 FindIt/UI/src + 工作区 cs2-ui-mod-toolkit 记忆）
- [ ] 搜索/分类（按分区类型/等级）
- [ ] 缩略图：图章落盘时渲染（ctrlC ThumbnailCameraTool 同款）或复用源建筑图
- 验收：搜名字→点条目→进入放置，全程不崩

### M4' 发布打磨
- [ ] 3619 个图章的全量性能（首启落盘耗时、加载分帧——ctrlC 协程每帧一个）

- [ ] PDX 发布

## 五、风险与待验证
1. PlacementTool 修复假设需一次游戏内验证（AUTO-TEST 已就绪，一轮启动即出结论）
2. 装饰的 SubArea 方案：源 prefab 的 Lot 数据结构与放置实体不同（prefab 声明 vs 实例 buffer），
   M2' 需对照 ctrlC ProcessSubElements（实体版）与资产编辑器 .cok 的写法（声明版）
3. 3619 全量注册的首启耗时（ctrlC 每帧一个的分帧策略必须抄）
