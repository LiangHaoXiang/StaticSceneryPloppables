# 服务建筑接入方案（已实现待实测）

> 状态：**已实现（2026-11-18），待用户游戏实测后发布 0.3.0**。基准代码 `e75847e`（0.2.0）。
> 游戏源码依据：本地 `.research/treectl/gamefull`（1.6.x 反编译快照）；服务建筑识别链路见 `Game.Prefabs/ServiceObject.cs`、`Game.Prefabs/ServicePrefab.cs`、`Game.City/CityService.cs`。

## 一、范围（已确认）

**纳入**（CityService 枚举四类）：

| CityService | 页签 key | 中文 | 英文 |
|---|---|---|---|
| `Education` | `Education` | 教育 | Education |
| `HealthcareAndDeathcare` | `Healthcare` | 医疗（含殡葬） | Healthcare |
| `FireAndRescue` | `FireRescue` | 消防 | Fire & Rescue |
| `PoliceAndAdministration` | `PoliceAdmin` | 治安与行政 | Police & Admin |

**排除**（本期不做，二期单独调研）：交通运输、水电、垃圾、通讯、公园类服务建筑——它们带功能性线网/管线声明（`ObjectSubNets` 为真实连接而非装饰），克隆放置的risk性质不同。

## 二、识别与数据（C#）

1. **扫描**：`ScanSources` 条件增加 `bp.Has<ServiceObject>()`；经辅助方法 `CityServiceOf(src)` 解析：
   `src.TryGet<ServiceObject>() → m_Service（ServicePrefab）→ 其实体的 ServiceData.m_Service（CityService 枚举）`，
   仅收上表四类（其余 ServiceObject 建筑直接跳过）。
2. **条目字段**：`Zone = 页签 key`（Education/Healthcare/FireRescue/PoliceAdmin，直接作为页签匹配值）；`Density = ""`（空，服务建筑不参与密度筛选）；`Level = 0`；`IsService = true`（新字段，图标与小字判定用）。
3. **排序**：`ZoneRank` 在工业（4）之后依次为 Education=5、Healthcare=6、FireRescue=7、PoliceAdmin=8、未知=9；密度为空排 0 不变。
4. **图标**：`RequestOptionalIcon` 原版图分支由 `IsSignature` 放宽为 `IsSignature || IsService`（服务建筑在 `Builtin.Atlas` 实测有图，同标志楼走 m_Icon / thumbnail:// 路径，失败回退分区图）。
5. **小字**：服务条目同标志楼——下方只显示尺寸（`WxD`），不显示等级（等级 0 无意义）。
6. **克隆**：白名单不变（不含 `ServiceObject` → 无服务/维护费/岗位；`PlaceableObject` 只挂在 StaticObject/Marker 上，建筑不带 → 无建造费用；无 Unique/解锁组件 → 可连放）。

## 三、UI（ssp-panel.tsx）

### 1. 页签

`ZONE_TABS` 由 6 个增至 **10 个**：全部 / 住宅 / 混合型住宅 / 商业 / 办公 / 工业 / 教育 / 医疗 / 消防 / 治安与行政。
页签行加 `flexWrap: "wrap"`（10 个 Chip 超出 700rem 单行宽，折为两行）。

### 2. 筛选面板行可见性与过滤生效矩阵（核心规则，请重点核对）

| 页签 | 风格行 | 密度行 | 等级行 | 面宽行 | 进深行 |
|---|---|---|---|---|---|
| 全部（All） | **隐藏** | **隐藏** | **隐藏** | 显示 | 显示 |
| 分区页签（住宅/混合/商业/办公/工业） | 显示 | 显示 | 显示 | 显示 | 显示 |
| 服务页签（教育/医疗/消防/治安行政） | **隐藏** | **隐藏** | **隐藏** | 显示 | 显示 |

**过滤生效语义（与可见性绑定）**：

- 风格 / 密度 / 等级三行：**隐藏时其过滤条件不生效**（已选的值保留在状态里但不参与过滤；切回分区页签自动恢复生效）。→ 只有分区页签下这三项才参与过滤。
- 面宽 / 进深两行：所有页签下都显示、**过滤始终生效**。

实现：`isZoned = ["Residential","MixedHousing","Commercial","Office","Industrial"].includes(filter.z)`；
渲染侧——风格/密度/等级三行仅 `isZoned` 时渲染，面宽/进深恒渲染；
过滤侧——`matchesFilter` 中风格/密度/等级三项判定以 `isZoned` 为前置条件（非分区页签时跳过这三项比较）。

### 3. 服务条目在「全部」页签下的行为

「全部」页签下风格/密度/等级行隐藏且不生效，因此服务条目**只受面宽/进深与搜索词约束**，与分区建筑混排（排序：分区建筑在前，四类服务依次在后）。

## 四、本地化（LocaleSSP + FALLBACK_EN）

新增 4 词条 ×11 语言：`Education` / `Healthcare` / `FireRescue` / `PoliceAdmin`（即页签文案；不再需要服务类型的密度 Chip 词条）。

## 五、预期规模与验证

- **数量**：基础四类估 40–60 栋 + DLC 增量；目录约 2260–2280 条，构建耗时 +约 0.1s。
- **日志验证**：构建完成时打印四类各自命中数（任一为 0 视为识别假设不成立，回报调整而非硬发）。
- **游戏实测清单**：
  1. 四个新页签内容正确、排序在各分区之后；「全部」页签混合排序正常。
  2. 服务页签下筛选面板只剩面宽/进深两行；「全部」页签五行齐全。
  3. 图标免 AIL 正常显示（同标志楼路径）。
  4. 放置/连放/迁移/拆除正常，**无道路前置、无费用扣除、无解锁门槛**。
  5. 地皮与周边装饰正常（服务建筑的 `SpawnableObject` 装饰随机性需实测；个别缺失则静态保留，可接受）。
  6. 存读档与卸载安全（机制与现有一致，白模可拆）。
